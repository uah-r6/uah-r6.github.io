# Trade semantics audit - 2026-10-01

This documents the existing implementation before the trade-window experiment. The full path is cached `data/research/derived/<folder>.json` -> `Match.from_dict` -> `calculate_match` in `research/pipeline.py` -> round and player-map `deaths_traded` / `kills_traded` -> `round_features` in `research/fit_models.py` -> `(deaths_traded - kills_traded)/rounds`. The normalized match cache retains kill order and timer seconds; the compressed player-map observations do not retain event detail. Changing windows therefore uses normalized cached matches, not `.rec` reparsing.

1. The initiating event is a processed opponent kill whose victim and killer are roster players and whose victim was alive. A kill with no killer, a teamkill and a suicide cannot initiate a trade. Kills are sorted by decreasing remaining round time, then source feedback sequence.
2. A later processed opponent kill completes it only if the later **victim is the earlier killer** and the later killer is on the earlier victim's team. Killing another opponent does not qualify. Intervening events do not cancel an opportunity.
3. The duration is `prior.remaining - later.remaining`, inclusive from zero to the configured window. A negative duration is rejected. `remaining` comes from siege-dissect `matchFeedback.timeInSeconds`; current Y11 `readTime` stores integral timer seconds. Thus a reported zero-second gap establishes source sequence, not subsecond order. At a threshold, clock quantization is material.
4. An eligible later kill can satisfy several earlier kills by the same killer. Earlier kill sequences are stored in a set; each earlier victim's `deaths_traded` is a boolean for that round. The later kill's `refrag_kills` counts once even if it trades several deaths. Each `kills_traded` belongs to the earlier killer and is counted once per earlier kill. `untraded_kills` is opponent kills less traded kills; `untraded_deaths` is deaths less boolean traded death. A chain can contain independent links in each direction.
5. A killer dying from an environmental/objective death event is not a refrag. Objective completions are separate events; credited objectives can satisfy KOST, but do not establish a trade. A final kill can complete an earlier opportunity, though it cannot subsequently be traded within that round. Matching restarts every round, so cross-round trades are impossible.
6. `deaths_traded` is credit for a victim whose killer was refragged. `kills_traded` is a penalty-side indicator that a player's kill was subsequently refragged. The research raw feature is `(deaths_traded - kills_traded)/rounds`, using the existing eight-second baseline. `refrag_kills` is separately tracked by the stats engine but absent from the research model. The live `collegiate_v1` rating uses several trade-dependent terms; research window experiments do not alter it.

The current design does not require that the later killer damaged the earlier killer before the finishing kill. It uses kill attribution only. It does not link same-timestamp events by subsecond packet times. The baseline is a project-defined hypothesis; this audit does not establish SiegeGG's private trade definition.
