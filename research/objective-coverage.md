# Objective coverage diagnostic — development events only

This check uses the 266 clean player-map rows from the seven pre-August training events and the 32 previously viewed August EWC development rows. Both September events are excluded. It compares player-map public objective counts to the tracker counts derived from siege-dissect `matchFeedback` completion events; it does not compare Rating values or alter the tracker.

| Development group | Clean player-map rows | Public plants | Replay plants | Public disables | Replay disables |
| --- | ---: | ---: | ---: | ---: | ---: |
| Seven pre-August training events | 266 | 55 | 23 | 7 | 1 |
| August EWC validation | 32 | 11 | 1 | 4 | 0 |

The difference is not only player attribution. In the June 25 North America Stage 1 100 Thieves–Five Fears Lair map (SiegeGG match 4150), the public game target records four plants across its ten players. The complete 11-round replay parses with 78 `Kill` feedback entries and **no plant or disable feedback entries**. Its normalized map therefore records zero plants. The raw siege-dissect JSON used for this check is cached under ignored `data/research/diagnostics/nal-stage1-100t-five-fears-lair-raw.json`.

This shows that the present objective feature is incomplete relative to the public target in this sample. It does not establish which underlying replay packets or SiegeGG definitions account for each difference. The expanded fit's nearly zero objective weight is therefore weak evidence about any true objective contribution. Do not infer missing plants from round wins or silently replace replay values with public target counts; investigate the underlying events and definitions on development replays first. KOST and the live `collegiate_v1` formula were not changed.

The same June replay does contain 1,297 copies of the packet tag that siege-dissect's `readDefuserTimer` listener watches. A read-only dump probe (`research/defuser_probe.py`) found timer strings ending at `0.023`, `0.024`, `0.048`, `0.054`, `0.090`, and `0.092`, but no string beginning `0.00`. The current completion branch in `third_party/siege-dissect/dissect/defuse.go` requires `strings.HasPrefix(timer, "0.00")`; this explains why these near-zero timer packets produce no completion feedback. The tag is present, so the listener itself is not simply absent. No threshold or completion rule was changed: a near-zero timer alone has not yet been validated as a completed plant or disable across multiple rounds and builds.

## Packet and actor audit — four development maps

`research/objective_timer_audit.py` now records each physical round's defuser timer runs and nearby Y11 per-entity scoreboard changes. `research/defuser_identity_probe.go` extracts the raw player identity refs for that read-only join. All output stays under ignored `data/research/diagnostics/`. The four audited maps are June 25 North America Lair (SiegeGG 4150), July 2 North America Chalet (4132), April 25 Asia Pacific map three (3585), and August 15 EWC map one (6156). Their public round logs are used **only to validate** packet hypotheses.

The old fixed-offset `readDefuserTimer` player ID is not a valid Y11 actor reference in the known June round: its four bytes do not match any of the ten `DissectID` values. The tag is a progress tick, not a player identity. A nearby +100 scoreboard change is useful evidence in some rounds, but is neither present nor unique for all plants and disables. This matches the limitations visible in [the upstream score-bonus approach](https://github.com/ImAAhmad/r6-dissect/blob/main/dissect/defuse.go); it is not sufficient for our parser to credit an objective.

### Independent completion-signal check

The previously observed `timer-run minimum <= 0.10 seconds` rule was held fixed before checking three additional development maps from distinct replay builds: NIP–Weibo Clubhouse (`Y10S4_01`, build `9486312`, SiegeGG 3073/5718), DZ–FaZe Clubhouse (`Y11S1_Alpha03`, `9658832`, 3554/6677), and LOUD–Black Dragons Lair (`Y11S2_Alpha04`, `9769907`, 4112/8360). Their 35 rounds contain 11 public objective rounds and 12 completion events (11 plants, one disable). The fixed rule found all 11 objective rounds with zero false positives or false negatives, and the number of qualifying timer runs matched the number of public completion events in every round. Across all seven audited maps, the same check covers 88 rounds, 27 objective rounds, and 32 completion events, with no round or completion-count disagreement. A stricter 0.05-second cut misses three of the independently checked objective rounds; 0.20 seconds yields one false positive in the original sample. Reproduce with `research/objective_timer_validation.py 3073 3554 4112`; the packet audits are in ignored `data/research/diagnostics/objective-timer-*.jsonl`.

This validates an **occurrence correlation** in these seven maps, not a production event detector or player attribution. The timer run boundaries are themselves heuristic, and public logs were used only to check the replay-derived signal. The low-level parser and live player objective counts remain unchanged. Plant and disable actors still require independent replay-derived identity evidence; score bonuses alone can collide with kills or other events.

### Actor-candidate check across all seven development maps — 2026-10-01

`research/objective_actor_audit.py` compares only cached packet-derived +100 score changes near the completed timer runs against public actors. The window is 2,000 bytes before to 20,000 bytes after the terminal timer packet; it is a diagnostic, not an attribution rule. There are 32 public events (27 plants, five disables). Sixteen have exactly one +100 candidate in that window: 12 exact username matches, one plausible documented alias (`JJBlazt` / `JJBlaztful`), and **three demonstrably wrong players** (3585 R6 `Souffle` vs `AZuKi86`, 3585 R8 `Lycolis` vs `Pikanzu`, 4112 R7 `Gabu` vs `RESETZ`). Five events have no candidate. All five disables have either multiple candidates or none. A unique +100 bonus therefore cannot safely identify even a planter, much less a disabler.

`research/objective_identity_offsets.py` separately dumped the 32 completion rounds and searched 32 bytes before to 159 bytes after each terminal timer tag. None of those local windows contained an exact four-byte player `DissectID` or a nearby scoreboard-style entity reference within 64 of one. This only rules out those simple local joins; an actor identity may live in a different event packet. The current timer listener's fixed-offset ID is therefore still unsuitable for Y11 actor attribution.

Public [replay-tool's defuser listener](https://github.com/wnc-replay/replay-tool/blob/main/dissect/defuse.go) uses lone-survivor inference and a later score-bonus fallback for newer replays. Its [bombPlant enrichment](https://github.com/wnc-replay/replay-tool/blob/main/enrich.go) starts with an already named plant feedback event, so it is not independent actor evidence for this project. These approaches are useful leads but do not overcome the observed score contradictions. At this actor-candidate stage, no production parser, KOST, objective credit, or Rating change was made. The next actor investigation should find a packet-level player-to-interaction link and validate it against these already held development rounds before considering UAH or model rederivation.

### Frozen entity-offset candidate fails broader development validation — 2026-10-01

The [predeclared plan](objective_actor_validation_plan.md) locked a narrower actor hypothesis before inspecting new public actor logs: a +100 score update within 2,000 decompressed bytes *after* a terminal `<=0.10` timer packet, with the score entity exactly four below the candidate player's `DissectID`, and exactly one candidate. It was selected after discovering the three wrong names above used entity offsets 8, 14, and 19. In the original 88-round discovery sample it named 17 of 32 public events: 15 exact names, two recognizable aliases, and no definite error. That was only an in-sample observation.

The first locked validation set (SiegeGG 3637, 4140, 4118) contains 35 rounds and five public plants. The timer criterion found five runs; the actor rule named four exact planters and left one unresolved. A second locked extension evaluated *all* 16 remaining cached, physical, single-folder development maps outside the original and first validation sets and outside the reserved North America Stage 2 final Rating event. These 168 rounds have 32 public objective events. The timer criterion found 35 runs, including **three runs in rounds with no public objective** (4141 R6/R14 and 4138 R9), while missing none of the 32 logged events. Two no-objective runs reached 0.007 and 0.005 seconds, so simply tightening the threshold to those values would not establish completion.

The unchanged actor rule named 22 of those 32 logged events: 17 exact public names, four clear name variants (`AquiX`/`Aqui`, `kondzz`/`kondz`, `Gotti5G`/`Gotti`, `Pikanzu`/`Pikan`), and **one wrong player**. In 4139 R7, the public log says **Raid** planted; the replay-derived candidate is **Aiden**, a separate SSG player with a different SiegeGG player ID (3862 vs 3749). Aiden received +100 at entity offset four and 1,419 bytes after the terminal timer packet; Raid received +10 later in the nearby packet stream. A +100 score event is therefore not sufficient actor proof even with this stricter entity join. Only one of eight total audited public disables was named correctly; the other seven were ambiguous or unresolved. The three public-log disagreements on timer occurrence and this definite wrong actor **reject the frozen production hypothesis**. The diagnostic code and ignored packet results are retained for further investigation. No low-level parser rule, live objective credit, Rating formula, private SQLite, or public website data was changed by this validation.

`research/objective_interaction_proximity.py` checked exact four-byte player `DissectID` values and scoreboard-style entity IDs within 4,096 bytes of both ends of the timer run in three critical examples. The true 4139 R7 Raid plant has no player reference of either form near the *start* of its timer run; near the end there are Aiden, Raid, and an opposing player's entity references. The 3880 R10 plant/disable has multiple players' entity references near the terminal packets. The 4141 R6 timer run without a public objective also has several nearby player entity references. No exact player `DissectID` hit appeared in these sampled windows. This local packet proximity cannot isolate the actor or distinguish completion from interruption.

The current public [replay-tool defuser listener](https://github.com/wnc-replay/replay-tool/blob/main/dissect/defuse.go) still derives newer-build actors from lone-survivor inference or a score-bonus fallback; its [binary format notes](https://github.com/wnc-replay/replay-tool/blob/main/docs/BINARY_FORMAT.md) describe the same timer ticks and label a separate float property only as a possible progress signal. Those sources provide no independently established actor-bearing packet to substitute here. A useful next packet experiment is to identify a planted/disabled state transition and its owner entity, then verify both against the wrong-actor and unlogged-timer examples before any parser change.

### Defuser-state property contrast — 2026-10-01

`research/objective_transition_probe.py` compared structured `0x23` entity TLVs after near-zero timer runs in the known wrong-actor plant (4139 R7), the 3880 R10 plant/disable, and the three unlogged near-zero runs. A typed one-byte property with raw hash bytes `ff 39 f4 08` appeared within 1,000 decompressed bytes after the terminal timer tick: value `01` after the logged plants and `00` after the logged disable, on one entity per round. It did not appear near the three unlogged timer runs. A separate property on the same entity, raw bytes `2f 5e 64 41`, changed from zero to a small integer after a plant in two examples. These are replay-derived structural observations; the property names and semantics are not established.

The same fixed `ff 39 f4 08` check was extended to **all 26 cached, non-reserved physical development maps** represented in existing objective diagnostics: 291 rounds, 61 rounds with public objectives (61 plants and eight disables), and 230 objective-free rounds. It matched `01` near 46/61 logged plant completions and `00` near 7/8 logged disables. Fifteen plants and one disable had no near-terminal state property. All three previously unlogged near-zero timer runs lacked the state change. `research/objective_state_negative_controls.py` then independently scanned every one of the 230 objective-free rounds for that exact typed property **anywhere in the decompressed round** and found zero occurrences. Results are cached under ignored `data/research/diagnostics/objective-transition-probe-all.json` and `objective-state-controls/`. This is strong development-sample specificity but incomplete sensitivity, and the public logs are validation labels, not parser input.

The raw property is **not by itself a disable detector**. In 4112 R11, a logged plant emitted `01` near its timer completion and a later `00` without a second near-zero timer run or public disable; the round ended with the attackers winning by `DefusedBomb`. A `00` can therefore also appear during later device cleanup. Any future occurrence rule needs the timer/state sequence and independent round-end checks. The property does not supply a player identity: the candidate parent/owner TLV (`0x0AD3AA3E`) had no link to the state entity in 4139 R7 or 3880 R10, and a ±512-byte player-reference check around the 4139 R7 state change found only **Aiden**, while the public planter was **Raid**. Nearby entity references are not actor proof.

`research/uah_objective_state_readonly.py` scanned all four private UAH archives without writing SQLite. The old stored Border `8a6357ff307c` R06 plant/disable rows coincide with `01` only, no `00`; that round's Attack side won. A different Border map, `076d2b6b02bc`, has `00` in R02 and R06, both labeled `DisabledDefuser` wins by the replay parser. This supports further investigation of state transitions but does **not** validate the historically credited disabler or assign any new UAH objective actor. The three scripts do not change the Go parser, Python adapter, stored statistics, public JSON, or Rating. Next investigate an independent interaction/owner packet that identifies the planter/disabler and test it on 4139 R7 and both UAH Border cases before any production extraction change.

### Read-only UAH audit and conservative historical safeguard — 2026-10-01

The local four-map SQLite was opened read-only. It contains 13 old objective event rows: **12 plants credited to defenders** and one role-compatible disable with no verified actor source. A read-only reparse of all four private archives under the current adapter emits zero verified objective actors. The same reparse reproduces all 89 currently stored tracked-player operator usage rows (the earlier 85-row checkpoint covered only three maps). The real SQLite and private archives were not modified.

The new statistics guard ignores stored objective rows unless a plant actor is on Attack, a disable actor is on Defense, and event/player teams agree. The Y11 adapter also no longer accepts `score_bonus_unique` as actor proof; only an explicitly verified player-packet source may be normalized. This leaves the original normalized replay data intact and changes no Rating formula. A temporary export from a migrated **backup copy** of the live DB, without touching public files, shows the only tracked-player aggregate affected by the role guard: Tallman3.14's Fall 2026 plants 5→0, KOST rounds 27→24, KOST 0.54→0.48, and `collegiate_v1` Rating 0.416700→0.374753. The existing public JSON has not been regenerated or published. The remaining role-compatible disable is still unverified and receives no new actor claim.

A wider development-data audit exposed false positives in the previously derived normalized data: 38 resolved plants were credited to defenders, four more to players with nil profile IDs that also resolve to defenders by username, and all five emitted disables had a different actor than the public round log. These 47 events are **not trustworthy objective observations**. The Python adapter now rejects role-impossible completions and requires an explicit verified actor source for Y11 completion events. This is a conservative data-integrity safeguard; it does not recover the real plants/disables. The low-level parser must provide an independently verified replay-derived actor signal before these events can be counted or the fitted objective weight interpreted. Raw replay archives and cached public targets remain available for rederivation.
